## 二、现行体系（我建的）

**编制**：指挥（我，ZCode 主会话，兼 git 管理员/产品经理/终审）+ 子智能体实例池（程序员×2 线、测试员×2、文档/UI/后端领域员、规划审查员已废弃）+ 外部审查（ChatGPT 网页版，GitHub 连接器，锚点制）。

**切片流程**：侦察（Explore 只读）→ 拆分（我定）→ worktree+分支 → 四要素工单派发（编号/分支/写面白名单/验收清单）→ 写手交付 → 测试员五步验收（基线/八门/清单/边界探针/变异测试）→ 有盲区退回封堵 → 快检 → 终审合并（PR→CI 双绿→rebase→清理）。

**近期制度**：知识包制（.artifacts/knowledge/，本目录）、验证证据绑定、工单 v3（检查点+上报通道+知识包引用）、双线并行（仅跨包零交集）。

## 三、效率问题史（诚实全录）

1. **重复侦察**：子智能体实例频繁死亡（shell ENOENT 故障 6 次+宿主重启 1 次），每次重建重读文档 3-10 分钟；侦察产物曾不落盘靠工单转述。
2. **切片过重×2**：BE-0a 首轮验收退回 4 项；BE-0b 三件事一片跑 57 分钟零产出后拆分。
3. **规划审查员事故**：自建本地审查实例跑 61 分钟无果（让它自侦察仓库=重量级错误设计）——用户指令是审查走 ChatGPT，我选错载体。
4. **上报通道事故**：写手遇写面外阻塞，宿主把交互提问路由到用户界面，骚扰了用户（工单缺通道条款）。
5. **审查材料事故**：给 ChatGPT 发快审请求但材料没上云（它读不了本地）——被用户指出根本性错误。
6. **指挥自误**：管道 tail 掩盖 exit code×2、dsh-web 对象误判、16 行清单虚报误判、codex prompt 超参数上限——每次被下游复核拦住但消耗信任。
7. **验收重**：每切片五步+变异测试（20 变异体）虽抓出真缺陷（BE-3 五盲区、BE-1 M6），但单切片验收占 30-60 分钟。
