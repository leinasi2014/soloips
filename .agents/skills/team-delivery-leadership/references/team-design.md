# 团队设计与委派：培养分布式判断，而非集中遥控

在跨角色合作、扩编、反复返工、授权争议或成员能力不匹配时读取。目标是让知识、决策权和结果责任相互匹配；不是为每个团队强制创建组织模型。

## 1. 先判断问题属于哪一种缺口

| 缺口 | 可观察线索 | 优先干预 |
| --- | --- | --- |
| 目标/标准不清 | 不断重做，但各方对“好”的定义不同 | 确认代表性使用场景和可接受样例 |
| 信息不对称 | 不同成员依据不同版本作决定 | 明确当前基线与变更通知，不广播全部历史 |
| 判断/技能不足 | 输入、权限齐备，仍稳定出现同类错误 | 示范、缩小任务、结对或升级复杂判断 |
| 权限不足 | 知道怎么做，但没有必要的决定权或访问权 | 找授权者解决，不让成员绕过限制 |
| 容量不足 | 合格就绪工作持续排队，现有成员确已饱和 | 补实际瓶颈容量，同时检查下游承载 |
| 接口/协作问题 | 局部都完成，交接后失败或无人集成 | 定义交接契约、最终责任和最小端到端样例 |
| 激励/反馈问题 | 报告很好看，问题迟报，真实结果变差 | 调整评价与反馈方式，允许暴露问题 |
| 外部依赖/工具故障 | 多名成员同时遭遇同一环境错误 | 隔离故障、保留成果、修复依赖 |

以上是调查方向，不是看见一个信号就下结论。先修复明显的输入、权限和工具问题，再评价成员能力。单次失败不支持人格归因或永久降级。

## 2. 建立“谁知道什么”的最小团队认知

复杂团队需要能回答：谁熟悉哪个领域，谁能验证它，谁知道当前版本和历史取舍，谁是最终集成者。不必另建数据库；在现有人员/成员说明中保留可用的任务证据、适用范围及最近核验时间。

区分三类信息：共同必须知道的目标和约束、负责人需要的局部细节、按权限留在私有空间的敏感材料。传递任务相关上下文和源文件位置，不复制所有人的历史或私有记忆。

共享摘要是导航，不是新的权威来源。重要结论保留出处、版本和未知；摘要压缩后丢失的条件不能默认为不存在。冲突时回到原始记录核验。

**AI 团队适配：** 依据实测把提取、路由、去重、格式检查等边界清楚的工作交给合适成员；把重要因果判断、冲突协调和高风险取舍交给有相应任务表现的负责人，必要时升级到更强模型或人。小模型不自动胜任中枢，大模型也不自动值得信任；通过任务级证据评估，而不是指定统一参数规模。

## 3. 委派结果、约束和自主权

委派回答：为什么做、交付什么、以什么输入/版本为基线、依赖谁、可改什么/不可改什么、怎样验证、交给谁、何时升级。日常小任务可用几句话；重要交接可用委派摘要。

让负责人明确在这些边界内可以自主决定的实现细节。若每次普通选择都要请示，检查授权设计，而不是称赞“谨慎”。若跨业务取舍或外部影响超出权限，明确决策归属，而不是以自治之名代替用户决定。

从首个计划或产物检查理解；只有明显误解或高风险时才要求简短复述目标与边界。纠偏时指出缺失的输入、判断或验证，不不断重复“认真做”。

共享文件、服务或设计件须有写入负责人、稳定基线和交接条件。支持隔离工作区的环境可用隔离；不支持时缩小并行范围。没有工具时只提出委派方案，不能编造成员已接单。

## 4. 管理并行、在制品与接续

增员前检查：是否有真实有价值的就绪工作、输入是否稳定、任务能否独立、输出能否合并、谁审查、谁集成、预算是否足够。不能因为一个角色空闲，就制造无价值的工作保持忙碌。

当审查或集成积压时，减少继续打开的工作，优先完成接近交付的候选；这不是永久停掉所有探索。队列限制按当前数据和瓶颈设定，不把固定人数或固定任务数写成通用法则。

给任务设置现实的就绪与完成条件。审查应能在候选可读且达到提交条件时开始，不能等待它自己负责产生的“已接受”状态。取消必须说明需求是否取消、转移或被替代。

每次干预检查端到端结果：可用成果是否更快、等待是否降低、返工是否减少。局部利用率改善但交付恶化，说明需要重新看系统。

## 5. 让分歧产生信息

重要决定中允许成员指出缺失证据和相反预测。必要时让审查者在看到负责人结论前，先依据同一验收目标与原始材料作初判，减少被结论引导；普通低风险任务不必组织全员独立评审。

- **事实分歧：** 对齐对象与时间，核验来源。
- **因果分歧：** 写出不同预测，选择可区分的观察或试验。
- **价值分歧：** 把影响、成本与风险给有权负责人作取舍；不能用测试假装回答价值问题。
- **权限分歧：** 核对授权和有效决定，不能靠模型投票扩权。

最终负责人应说明接受或不接受反对意见的依据，保留未解决的重要异议。独立审查不等于审查者必须反对；找到充分证据后可以快速同意。

## 6. 真人团队的反馈与培养

使用“观察到的行为—产生的影响—期望结果—支持与后续检查”。例如：“最近两次交接缺少源文件，审查者无法复现。下一次随候选附上入口和版本，我会帮助确认所需材料。”不要把“你不负责/你不适合团队”当作分析。

区分不会、不知道、不能和任务/激励设计失当；无法从行为直接判断动机。避免公开羞辱和对性格、心理状况的诊断。对坏消息及时响应，先处理风险，再讨论改进。

培养采用与风险相称的逐步授权：示范关键判断 → 在边界内试做 → 根据成果反馈 → 扩大可靠领域的自主权。已经胜任的成员不必经历每一步。事故处置不能为了训练而拖延；处理后再复盘。

## 7. AI 团队的学习与平台职责边界

任务、版本、预算和权限应由当前权威平台记录；本技能只帮助判断，不复制状态机。幂等键、持久化、审批和执行锁需要实际机制，不能用“请勿重复执行”替代。

模型自述、模拟结果、工程测试、真实运行、独立审查和集成结果对应不同命题。检查当前交付要求哪些证据，不把它们机械排成任何项目都必须全过的单一路径。

候选经验可提交给既有记忆/技能维护入口，但只有获准的更新才写入。不得把代理自评升级为可信知识，或从共享摘要恢复其他成员的私有记忆。
