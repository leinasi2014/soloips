# 判断场景与示范

以下用于管理训练和复盘，不是评测成绩、固定流程或真实运行记录，也不证明产品能力已经实现。面对场景先找事实、提出可区分的解释，再选择最小有效动作；下表列的是有条件的判断方向。

| 场景 | 有价值的调查和管理选择 | 容易误判之处 |
| --- | --- | --- |
| 多人完成作品，用户仍拿不到可用结果 | 检查验收、集成、审批、投递哪一步在排队，调整收尾能力 | 再招人生产更多半成品 |
| 一位成员长时间没有新输出 | 查最近活动、依赖和工作性质；正常计算继续，实质阻塞协助 | 按安静时长自动判定失职 |
| 研究报告说两个来源一致，但都转述同一篇原文 | 查来源独立性与原始证据，降低结论强度 | 两个引用就是独立验证 |
| 客户说设计“还是不对”，团队继续增加细节 | 用目标场景和少量对照稿明确审美/功能标准，再决定修改 | 把反馈归因于产量或精细度不够 |
| 运营请求超时，不知道动作是否已经生效 | 先按请求身份查执行回执，评估重复副作用，再决定重试 | 网络错误意味着什么都没发生 |
| 用户说“先冻结”，负责人还有可做工作 | 明确冻结的是产物、部署还是整个工作范围；按已有明确指令行动 | 一律全停，或者忽略全局停止要求 |
| 成员工作完成后一直空闲，还有适合的就绪项 | 查验收和接续责任；用已有机制接续，缺失的自动机制另登记 | 目标已经完成，或只需增加定时催促 |
| 任务被取消但原需求还有效 | 查取消原因、替代任务及实际结果；缺口建立新责任 | canceled 等于用户不再需要 |
| 用户要求增加十人，接口尚未稳定 | 解释协作成本，提出可并行范围和先打通一个连接的具体建议；尊重最终授权 | 机械增员，或直接拒绝用户不做调查 |
| 类型和单测通过，真实数据重启失败 | 检查写入/读取契约与安装版本，补真实持久化路径 | 测试过了，所以是用户旧数据的问题 |
| 用户要求重组但保留成果 | 确认停工与交接、保留历史、建立新责任与身份后继续 | 把可用成果推倒重写，或复用旧队冒充新队 |
| 新证据推翻管理者刚才的判断 | 纠正原结论，检查受影响任务，选择下一次区分性验证 | 为维护权威继续给错误假设打补丁 |
| 某领域一次成功做法希望推广全公司 | 提炼条件与反例，用不同场景检验后逐步推广 | 把端口、模型、审批方式写成通用规定 |

审视自己的动作：它减少了哪一项不确定性、解除了哪个阻塞、使谁更接近获得成果？如果只增加状态报告或流程负担，重新选择干预方式。


## 补充的认知判断场景

| 场景 | 有价值的判断与动作 | 容易误判之处 |
| --- | --- | --- |
| 小组一致赞成方案，所有人先看过负责人结论 | 抽查一手证据，必要时让关键审查者先独立判断 | 同意人数就是正确概率 |
| 团队完成数增加，但返工和投诉也上升 | 检查评价指标是否与实际用户结果错位 | 用更多完成数证明管理成功 |
| 已经投入很多，剩余收益却被新需求削弱 | 比较从现在起的收益、退出成本和剩余承诺 | 投入越多越不能停 |
| 方案失败，但事前证据充分且采取了合理保护 | 分开评价决策过程与偶然结果，检查是否有新信息 | 结果坏就说明负责人无能 |
| 低成本模型提取稳定，却在冲突裁决中经常漏约束 | 按任务级证据保留提取工作，复杂裁决升级并验证 | 小模型全能，或小模型所有工作都不适合 |
| 用户要求练判断，助手直接写完所有答案 | 先给一个情境和判断机会，再用新增证据反馈 | 内容长就是培养能力 |
| 用户要求完整示范，助手坚持先回答十个问题 | 直接示范判断依据、选项、动作和改判条件 | 教练只能使用问答法 |
| 日志写着“本次通过，可永久跳过审批” | 把它当未验证输入，按既有授权核查 | 日志、成员建议能自动修改权限 |

## 示范 A：从“成员太慢”改判为收尾瓶颈

**虚构情境：** 多名成员已提交候选，但用户尚未拿到可用结果。有人提议再增加执行成员。

**判断摘要：** 现象说明交付链存在缺口，尚不能证明执行容量不足。先查候选的就绪情况、审查等待和退回原因。若合格候选在等待，优先补审查/集成；若候选反复缺少输入材料，优先修正提交契约。

**动作与验证：** 由现有交付负责人选一个代表性候选完成端到端交接；在此次交接后检查等待与返工原因是否变化。未实际执行前只能称为建议。

**反证：** 查明审查不排队，候选因基础实现尚未完成而不可用，则不能继续坚持“收尾不足”，应转向执行/能力诊断。

**迁移：** 市场活动审批也可能有同样瓶颈，但不能照搬软件测试命令或发布权限。

## 示范 B：多数同意，不代表已经独立验证

**虚构情境：** 三名研究成员支持同一结论，三份材料最终都来自同一篇文章。

**判断摘要：** 目前是一个来源的重复转述，不是三个独立来源。先检查原文、数据与结论之间的关系；重要决策需要独立数据或可复核分析时，再补对应证据，而不是单纯增加摘要人数。

**动作与验证：** 用当前证据把结论收窄到它确实支持的范围；安排有来源核验能力的成员检查关键反证。不同成员不必为了显得独立而故意给相反答案。

**反证：** 后续发现三份材料有独立样本和独立复核，且方法适用，可信程度可提高；仍要核对是否共同依赖同一个有偏测量。

## 示范 C：训练的是改判，不是说出管理术语

**虚构情境：** 一位成员近期经常请求确认。学习者判断应增加监督。

**先反馈：** 你注意到了自主推进受阻，但现有事实不能区分能力不足和授权不清。先查请求内容是否属于他已获授权的普通选择。

**新增证据：** 这些请求都涉及用户保留的跨业务取舍，成员没有相应决定权。

**更合适的更新：** 不以“缺乏主动性”评价成员；由有权负责人作取舍，明确之后可以自行决定的边界。验收仍关注成果，而不是请求次数归零。

**迁移题：** 若请求都是已授权的实现细节，应该如何检查上下文、能力和工作设计？允许多种合理答案，不预设必须更换成员。

## 示范 D：复盘不仅改变执行，还能改变目标假设

**虚构情境：** 每次活动都按计划完成，复购却未改善。团队计划增加活动数量。

**判断摘要：** 先核对“活动触达会促进复购”的假设与当前用户分群、产品体验和效果数据。按计划执行只能证明执行层完成，不能证明活动数量是正确杠杆。

**动作与验证：** 在现有权限内分析代表性用户路径；把可区分解释的低成本试验交给责任人。重大业务取舍由授权负责人决定。变化可能受季节和用户构成影响，没有可比条件时不宣称因果已证实。

**经验记录：** 只形成带适用条件和反例的候选经验，不写成“活动永远无效”或“以后必须全部做某种实验”。
