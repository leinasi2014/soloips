# 认知判断：把“想得更深”变成可检验的选择

只在证据冲突、原因不明或重大取舍时展开。不是每个任务都要套一遍模型；最后应产生行动或明确的决策阻塞，而非更多术语。

## 1. 先识别自己正在回答哪一层问题

| 层次 | 要回答的问题 | 常见错位 |
| --- | --- | --- |
| 目标 | 我们要改善谁的什么结果？ | 认真优化已经失效的需求 |
| 系统 | 工作、信息、权限和反馈如何相互影响？ | 所有延误都归因于个人 |
| 决策 | 当前应选择什么，放弃什么，为什么？ | 用无限调查逃避取舍 |
| 执行 | 谁在何种边界内完成什么？ | 只有策略，没有责任 |
| 学习 | 哪项预测错了，规则应该如何修正？ | 只总结结果，不修正认识 |

层次是观察角度，不是汇报格式。团队执行很快却用户不买账，先回到目标与使用证据，而不是再优化执行速度。

## 2. 建立最小证据账，不制造第二套真相

只记录会改变选择的内容，复用任务、文档或当前答复：

- **事实：** 实际观察、来源、对象/版本、时间、适用范围。转述写成“某人报告”，核验后再升级结论。
- **解释/假设：** 哪种机制可能造成现象？哪些前提尚未得到支持？
- **决定：** 谁在什么权限内基于哪些证据选择了什么？决定本身不是事实验证。
- **未知：** 缺什么、为什么重要、不查是否仍能安全前进？

按证据与命题的匹配程度判断，不建立机械的“来源等级”：真实环境一次成功也可能样本不足；稳定的自动化测试也只能覆盖它实际检查的路径。

核对出处独立性：三份报告引同一来源仍是一条证据链。不同模型读相同上下文得到相同结论，是一致性线索，不是三个独立实验。证据越过适用版本、数据群体或环境时，重新核验。

## 3. 用竞争解释进行因果诊断

对重要且不明确的问题，采用以下思路；不必公开逐步思考，只交付可核验的摘要。

1. 把现象写成不带归因的描述，例如“最近三个任务在提交后等待接受”，而非“成员懒散”。
2. 选择真实可行的竞争解释，例如“验收容量不足”与“提交不满足输入契约”；有清楚证据时不强行增加解释。
3. 给解释找不同的可观察预测。容量不足通常伴随合格候选排队；契约不符通常伴随退回和缺失字段。
4. 选择低成本、最能改变行动的检查：抽查代表性候选及审查记录，未必需要重跑整个项目。
5. 按结果修改结论、动作和依赖该结论的任务。仍不能区分时保留不确定性，选择有保护边界的试验。

不要把时间先后当因果，也不要把一次干预后的改善全归功于干预。检查同时发生的任务难度、输入、团队容量和环境变化。无法控制时明确“相关变化/候选解释”，不写“已证明根因”。

## 4. 识别会改变管理行为的偏差

| 信号 | 有用的纠偏问题 | 不该做的事 |
| --- | --- | --- |
| 总在找支持既有方案的材料 | 哪个可观察结果会使我放弃它？ | 为反对而反对、无限找反例 |
| “已经花了很多，不能停” | 从现在起的收益是否值得剩余投入？ | 无视切换、退出和已承诺责任的成本 |
| “最强模型/资深成员这么说” | 它依据什么？此任务上的记录如何？ | 用身份代替验证，或一概否定专家 |
| 结果好就认为方法好 | 当时可得证据支持这个选择吗？换一次能重复吗？ | 用事后信息惩罚当时合理决定 |
| 大家都同意，没有分歧 | 是否共享同一来源、受到同一个结论引导？ | 机械增加“反对者”或靠票数验收 |
| 有了新经验就到处推广 | 哪些条件不同会使它失效？ | 把局部案例写成全局硬规则 |
| 只追求完成数量 | 返工、用户效果和下游排队是否变差？ | 新建一个同样容易被刷高的单一指标 |

这些是检查视角，不是给成员贴“有偏差”的标签。先检查自己的判断。

## 5. 用决策经济性控制思考成本

对重要决策比较真实选项，包括必要时维持现状、缩小范围、先试点或停止。描述收益、代价、依赖、最坏影响及回退路径；不把它们硬塞进缺乏数据的精确总分。

**信息价值：** 新证据有多大可能改变选择？改变选择能避免什么损失？获取证据会付出多少时间、预算和风险？用定性比较即可；没有数据不要捏造概率或收益数字。

**可逆性：** 可恢复不等于无副作用。检查是否涉及外部发送、收费、公开承诺、敏感信息传播或不可重建状态；本地回滚无法撤销已经发生的外部影响。

**事前失败检查：** 高影响决定执行前，假设未达到目标，找最可能的少量失败机制及早期信号。把它们转成验证、隔离或回退措施，不扩张为无穷风险清单。紧急情况下先采取获准的止损措施。

**停止调查：** 合理选项在现有不确定性下都导向同一个低风险动作，或额外信息价值低于延迟代价时，行动更有价值。高风险关键证据缺失则缩小范围或升级，不能把“避免分析瘫痪”当作绕过授权的理由。

## 6. 让决定留下可观察的预测

把重要判断表达为：

> 目前更支持〔解释〕，依据是〔证据〕，仍缺〔未知〕。选择〔动作〕，由〔负责人〕执行。预期在〔合理时点/事件〕看到〔变化〕；出现〔反证/风险〕就改判、暂停或回退。

置信度默认用低/中/高并说明依据。只有事件定义、观察期限和判定标准都明确且概率有用途时才记录概率；主观估计注明性质，不装作统计测量。

复盘按事先定义判定预测。更改问题、期限或指标要留痕，不能事后重写命中标准。比较一系列可比判断才能谈校准；样本少时给具体误判实例，不宣称普遍能力提高。

## 7. 抽象与迁移

从案例提炼“条件—机制—动作—反例”，再换场景检验：例如代码评审排队与设计审批排队可能共享收尾瓶颈，但验收证据和权限不同。先确认可迁移的机制，再适配动作；不是把软件命令照搬进真人团队。

需要改变的不是术语数量，而是能否更快排除错误解释、选择有效杠杆，并在反证出现时真正改变决定。
