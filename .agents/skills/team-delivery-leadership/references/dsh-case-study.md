# DSH 条件性案例

本案例来自 DSH 团队重构。仅在相同平台和用户约定下适用，不作为其他团队的默认配置或审批规则。通用思维是分清配置与执行、保护成果、核对真实身份和证据边界。实例路径、端口与模型值从当前部署查询；本文件不授权清理任何目录。

## PTC 与 RLM

- 官方预设由 agent-presets 提供。已验证的一种配置是 settings 的 `agent-presets.default: ptc`；实际版本需先查支持字段并读回 UI。子代理继承行为也要检查，不能仅看主输入框写着 PTC。
- PTC 用 `run_code` 呈现工具组合。实际 schema 为准，不能把不再直接暴露的 shell/glob 名字当顶层工具调用。工具呈现不会扩大权限。
- RLM 需安装在目标 DSH Profile，并在插件树启用；宿主加载、Web 配置显示、模型侧工具存在、实际一次成功调用是不同证据。不能拿 Codex 的技能安装代替 DSH 插件安装。
- 重组前保留已生效的凭据引用和权限；不要把模型名、RLM 和权限模式混成一个设置。

## Windows Web 边界

用户要求浏览器选工作区时，在点击前核对 Profile：禁用 `directory-picker`，配置 `directory-browse` / `directory-ui-browse` 对应官方 Web 浏览实现。先查实际包导出和组合结果，不能点击后才发现打开了原生对话框。

后台宿主、命令执行器及其子进程都要无可见控制台；隐藏主进程不证明子进程隐藏。保留取消、退出码、日志重定向与进程约束。模型 API 访问本身不要求启动本地 WorkBuddy 客户端。

## 冻结与清队

1. 以用户指定实例为界，停止派工、自动领取、待处理审批以及会恢复执行的定时任务。使用原生停止接口并核对实际执行，不只信队长“已停工”的回复。
2. 保存任务、候选、会话、必要附件与配置引用，建立可读交接。验证备份内容和可读性；敏感记录留在获准本地位置，不拷进公共仓库或发送给所有模型。
3. 用户要求删除时才进行删除。默认使用正式退队/删除入口；有 preview、revision、requestId 时核对范围、保护对象和幂等结果。归档、移除入口和新建是不同操作，不互相冒充。
4. 如果加载故障导致正式接口不可用，先报告具体阻塞。只有用户已明确要求清除该实例全部相关状态且工作记录保留范围验证完成时，才能考虑停服后的离线迁出；验证进程已停、绝对路径限定实例、备份目标不覆盖，操作后核对空状态。这属于特殊恢复处置，不是通用修复，也不证明正式删除功能可用。没有这种授权时保留状态并请示。
5. 新 Team、队长、成员和任务使用新身份；旧成果作为输入引用，不能恢复旧 attempt 或复用旧队冒充新队。重组不是把已完成成果推倒重写。
6. 先对齐需求与候选缺口，再建任务。新队基础配置和准入验证后才能开工；定时任务在用户授权范围内恢复，不能因重启自动解除冻结。

## 交接最小内容

保存：当前权威入口、用户有效决定、目标服务与包身份、已安装成果及验证边界、未集成候选、剩余需求/缺陷、取消任务去向、所有权、停止情况和恢复条件。

一次性的实例路径、错误日志、任务 ID 和备份哈希写入该次交接，不固化为技能默认值。

## 本案例的故障约定

该项目用户要求上游 API 错误立即停止受影响执行并通知用户，保留团队和任务，恢复需明确指示；短信/邮箱只预留接口。此约定不得外推为所有团队的统一重试策略。GLM 仅文档同样是该项目的用户分工决定。
