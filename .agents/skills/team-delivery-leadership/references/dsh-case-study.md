# DSH 条件性案例

**来源与验证边界：** 本文件保留用户上传原版中的 DSH 团队重构经验。本次更新未连接 DSH、检查当前部署或验证下面的接口/配置；历史记录不是当前能力证明。仅在相同平台、版本适配且用户约定仍有效时使用。原版的一次性约定不得升级为全局默认规则。

通用思维是分清配置与执行、保护成果、核对真实身份和证据边界。实例路径、端口与模型值从当前部署查询；本文件不授权清理任何目录，也不假设某个工具已安装。
**SoloIPs 当前路线请读 [项目与开发迭代](soloips-development.md)。** 本案例包含旧 `dsh-agent-swarm` 阶段的管理与重组经验；它只提供反例和取证方法，不是当前官方 Agent Team 的接口、配置或运行规程，也不授权重新安装旧 swarm。

## PTC 与 RLM

- 原版记录官方预设由 agent-presets 提供，并记录过 settings 的 `agent-presets.default: ptc`。当前操作前先核对实际版本支持的字段、插件来源与组合结果，再读回 UI；不能把这段历史文字当成当前 schema。子代理继承也需验证，主输入框显示 PTC 不代表全队已生效。
- 原版 PTC 案例使用 `run_code` 呈现工具组合。当前以实际暴露的 schema 为准，不能把不再直接暴露的 shell/glob 名字当顶层工具调用。工具呈现不扩大权限。
- RLM 在本案例中需要安装于目标 DSH Profile 并在插件树启用。宿主加载、Web 配置显示、模型侧工具存在和真实一次成功调用是不同证据；不能拿 Codex 的技能安装代替 DSH 插件安装。当前实现需重新核对。
- 重组前保留已生效的凭据引用和权限边界；不要把模型名、RLM 和权限模式混成一个设置，不在交接中扩散凭据内容。

## Windows Web 边界

原版案例中，用户要求在浏览器选择工作区，采用禁用 `directory-picker`、配置 `directory-browse` / `directory-ui-browse` 对应 Web 浏览实现的方式。当前先核对 Profile、实际包导出、支持配置和组合结果，不能假定这些名称仍适用或是唯一实现。交付验证应确认真实用户路径没有打开不期望的原生对话框。

本案例要求后台宿主、命令执行器及其子进程无可见控制台；隐藏主进程不证明子进程隐藏。保留取消、退出码、日志重定向与进程约束。原版不把本地 WorkBuddy 客户端作为模型 API 访问的必然前提；当前依赖关系仍按实际部署核验。

## 冻结与清队

1. 以用户指定实例为界，按授权停止派工、自动领取、待处理审批以及会恢复执行的定时任务。使用原生停止接口并核对实际执行，不只信队长“已停工”的回复。
2. 保存任务、候选、会话、必要附件与配置引用，建立可读交接。验证备份内容和可读性；敏感记录留在获准位置，不拷进公共仓库或发送给所有模型。
3. 用户要求删除时才删除。默认使用正式退队/删除入口；有 preview、revision、requestId 等机制时核对范围、保护对象和幂等结果，不假定这些字段一定存在。归档、移除入口和新建是不同操作，不互相冒充。
4. 正式接口不可用先报告具体阻塞。只有用户已明确要求清除该实例全部相关状态，且工作记录保留范围验证完成时，才能考虑停服后的可恢复离线迁出；验证进程已停、绝对路径限定实例、备份目标不覆盖，操作后核对空状态。没有相应授权则保留状态并请示。这是特殊恢复处置，不证明正式删除功能可用。
5. 要求新队时，新 Team、队长、成员和任务使用真实新身份；旧成果作为输入引用，不恢复旧 attempt 或复用旧队冒充新队。重组不是把已完成成果推倒重写。
6. 先对齐需求与候选缺口，再建任务。基础配置和准入验证后才能开工；定时任务只在用户授权范围内恢复，不能因重启自动解除冻结。

## 交接最小内容

保存当前权威入口、用户有效决定、目标服务与包身份、已安装成果及验证边界、未集成候选、剩余需求/缺陷、取消任务去向、所有权、停止情况和恢复条件。

一次性的实例路径、错误日志、任务 ID 和备份哈希写入该次交接，不固化为技能默认值。

## 本案例的故障约定

原版项目用户要求：上游 API 错误立即停止受影响执行并通知用户，保留团队和任务，恢复需明确指示；短信/邮箱只预留接口。当前项目仍适用该约定时严格遵循，不因通用技能允许有条件重试而覆盖它。此约定不得外推为所有团队的统一重试策略。GLM 仅文档同样是原版该项目的分工决定，不是通用模型能力结论。
