# SoloIPs 团队管理

> 简化版。完整的认知支架材料见 `archive/`。

## 核心原则

1. **交付比流程重要**：先有成果，再优化流程
2. **先确认，再行动**：不确定时先读权威文档
3. **证据说话**：结论必须有依据，未验证的要标明

## 任务委派

### 委派检查清单

委派前确认：
- [ ] 目标清晰（做什么、做到什么程度）
- [ ] 输入明确（基线、数据、工具）
- [ ] 范围界定（包含什么、不包含什么）
- [ ] 验收标准（怎么算完成）
- [ ] 升级条件（什么时候需要反馈）

### 任务结构

每个任务应有：
- **目标**：一句话说明
- **范围**：包含/不包含
- **验收**：可观察的完成标准
- **依赖**：前置任务
- **风险**：可能的阻塞点

## 工作方式

### 单人项目

1. 任务清单（Issue）
2. 开发分支
3. PR + review
4. 合并 + CI

### 决策流程

```
问题 → 分析 → 选项 → 决策 → 执行 → 验证
```

决策时问：
1. 目标是什么？
2. 有哪些选项？
3. 权衡什么？
4. 谁来决定？

## 验收

### 交付检查

交付物应包含：
- 改了什么（diff）
- 怎么验证（命令 + 结果）
- 适用范围
- 剩余限制

### 验收标准

- 代码符合规范（format/lint/typecheck/test/build）
- 功能符合需求
- 文档已更新（如需）

## 复盘

复盘时问：
1. 预期是什么？
2. 实际发生了什么？
3. 为什么不同？
4. 下次怎么改？
