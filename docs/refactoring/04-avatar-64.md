# AVATAR-64：头像生成与偏好改版

**状态：已确认需求（2026-09-15 用户决定）；下列目标不表示当前安装版本已经支持。** 新重构仅接受原生 64×64；删除旧 8..32 尺寸分支、常量和过时规则，不以旧资产兼容作为当前开发目标。头像展示最大 64 CSS px，不作 2 倍或更大放大，小型聊天位置可缩小。

- **AVATAR-64-01：** 沿用本人先保存并读回文字资料、再生成头像的所有权与顺序；64×64 网格编译、安全 SVG 校验、RPC 读取及前端解析必须一致；非 64 尺寸明确拒绝。继续限制调色板、矩形数和资产大小，保留 SVG 安全白名单、16,384 字符与 256 矩形上限；不能通过放宽安全校验完成尺寸升级。
- **AVATAR-64-02：** 在既有插件设置提供“头像生成偏好”文本项。未配置、空字符串或纯空白使用默认“优先人物、动物，物品和抽象图案为次选”；填写后按自定义视觉要求引导。该倾向不是精确概率或分类保证，不新增权重调度系统。
- **AVATAR-64-03：** 偏好经现有配置机制保存，重启后保留，并在成员后续生成时成为有界的视觉输入；不得成为人格、记忆、工具权限或任务指令。生效范围跟随现有插件配置作用域，不暗增部门级覆盖。变更不批量覆盖已有头像；本人主动重生成时使用当前偏好。
- **AVATAR-64-04：** 验收涵盖原生 64 网格、非 64 拒绝、非法/超界输入拒绝、配置空白默认与自定义/清空恢复、保存重启及真实模型输入、实际 64 CSS px 显示和人物/动物样例视觉检查。结构测试成功不等于画面好看，模型口头说明不等于实际配置已生效。

- **AVATAR-64-05：** 所有生成或改图提示词必须包含“整合细碎的细节为更干净的面。”成功样例覆盖实际读写和展示；安全反例使用合法 64 尺寸，避免只因尺寸错误拒绝而掩盖安全漏洞。普通 UI 图标尺寸不属于头像资产合同。

头像是[ORG-03 完整入职](02-company-contract.md#112-权限个性与入职)的一部分，头像补齐不能代替其他必要入职项。
