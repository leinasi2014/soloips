### 10.1 术语、标签与现有边界

| 术语 | 本节含义 | 不能据此推导的结论 |
|---|---|---|
| 部门 | 围绕长期职责组织人员、岗位、政策和获准知识的组织单位 | 不是某次群聊、任务或队长会话的别名 |
| 岗位 | 一组职责、所需能力及评价条件 | 不等于某个固定模型或员工 |
| 员工 | 可以经历不同任职的长期个体身份；管理员也是承担管理岗位的员工 | 不等于一个 Session；不声称模型具有真实意识 |
| 任职 | 员工在某部门、岗位及授权范围内的一段任用关系 | 调岗不使旧部门资料自动获准在新部门使用 |
| Team / Session | 沿用现有协作与执行合同 | 用量聚合、会话续接不提供组织身份权威 |
| 记忆 / Skill | 有来源的工作知识 / 可重复使用的方法与资源 | 保存、批准、分配、实际加载和有效使用是不同事实 |
| 污染 | 错误、失效或超出适用范围的内容影响当前判断的具体问题 | 风格不同、个性开放、员工与管理员意见不同本身不构成污染 |

本节使用两组独立标签：**〔需求〕**为用户已明确的要求，**〔约束〕**为既有项目规则，**〔建议〕**为待采用设计，**〔待决〕**为尚未确定的选择；**〔源码事实〕**仅说明指定实现，**〔推断〕**说明推理结论，**〔未验证〕**说明证据缺口。需求成立不证明实现完成；建议中的“必须”只描述该方案成立所需条件。

- **CUR-01〔源码事实〕**：现有私有记忆分区使用 scope、Team 与成员 Session，见 [member-private-memory-service.ts 的固定版本](https://github.com/leinasi2014/dsh-agent-swarm/blob/51ddbe29bf35f39064cd99269d824e0b3a9e856d/src/runtime/member-private-memory-service.ts#L36-L43) 中的 `OwningMember`。未来按部门、岗位、任职隔离是设计，不是该分区已支持的事实。
- **CUR-02〔源码事实〕**：现有成员恢复核对 `stored.meta.parentSession` 与恢复队长的 ID，不一致返回失败并要求 drain，见 [member-provisioning.ts 的固定版本](https://github.com/leinasi2014/dsh-agent-swarm/blob/51ddbe29bf35f39064cd99269d824e0b3a9e856d/src/runtime/member-provisioning.ts#L546-L563)。**〔推断〕**只改管理员绑定不足以完成接管；本轮没有执行该故障的运行时实验。
- **CUR-03〔约束〕**：Team 继续拥有任务、attempt、审核、邮箱、依赖及预算的既有状态；Session 日志继续记录执行事实。部门不复制第二份任务状态机。扩展遵循[DSH 分层原则](../01-dsh-principles.md)。
- **CUR-04〔未验证〕**：部门实体存储、长期员工与任职接入、受支持的会话迁移、完整入职门及个人档案彻底删除均没有本节所需的完整实现证据。源码检索未见不等于官方没有能力；接入前核对目标安装包与真实组合，不改变现有兼容基线。

CUR-01/02 的源码观察基线为 `51ddbe29bf35f39064cd99269d824e0b3a9e856d`，核对日期为 2026-09-14；源码变化后应重核受影响结论。代码观察、设计走查和产品验收分别记录。

### 10.5 招募、入职与人员变动〔建议〕

**DEP-D04：初始化不依赖正式领任务。** 外部获授权操作者先建立部门及首任管理员的合法会话；管理员通过自身入职检查后才开放招募职责。管理员招募的员工先进入入职阶段，完成 DEP-R03 所列内容。尚无管理员时由谁任命、是否设置代理及其期限由 DEP-O01 决定，不能由候选管理员自批授权。

入职检查读取实际资料与文件，检查非空有效内容、所有者/任职绑定，以及执行上下文对操作文档的正确引用；头像不是占位图或仅口头声称存在。文件数量合格不等于人格质量已被验证。未就绪人员可以补资料，正式派单、自领和自动调度都不得绕过检查。缺项返回原因，重试有界且可恢复，不反复重建员工身份。

**DEP-D05：变动先处理旧执行，再启用新关系。** 共同路径为：核对获授权决定 → 阻止受影响的旧派工/唤醒 → 确认在途动作终止或获准移交 → 处理排队消息与任务归属 → 更新组织关系及合法执行映射 → 读回并验证恢复。取消请求不等于执行已停，多域写入不声称共同原子提交；无法确认旧动作状态时不允许同一工作双重执行。

| 事件 | 关系与知识处置 | 恢复/失败边界 |
|---|---|---|
| 管理员替换 | 保留部门和员工身份；撤销旧管理资格，处理其在途工作及消息后绑定新任职 | 验证成员冷恢复和任务续接；不能只改显示名或队长绑定 |
| 调岗 | 结束旧任职并建立新任职；默认停用旧岗位记忆与 Skills，按授权选取可迁移经验 | 新会话不注入整段旧上下文；旧知识可读范围见 DEP-O04 |
| 冷处理 | 保留档案，停止该员工全部业务执行、正式派工与自动唤醒；只有已移交给其他合法执行者的工作可继续 | 未确认停止或移交不得报告冷处理完成；恢复时重核当前岗位、权限和知识版本，不自动复活旧权限 |
| 真实解雇 | 按 10.8 完成交接、停止执行、删除个人档案，保留必要人事过程 | 同一办理记录恢复失败步骤，未核清清单不得报告全部删除 |
| 部门暂停/撤销 | 暂停先阻止新增工作；撤销必须明确员工去向及资产归属 | 不等于批量解雇；处置未定不得自动删除人员与知识，见 DEP-O01 |

### 10.6 记忆、个人成长与 Skills〔建议〕

**DEP-D06：保存、启用和共享分别控制。** 调岗后的员工保留长期身份，不自动获得旧部门记忆在新岗位的使用权。隔离需要实际检索过滤、授权检查和上下文装配共同保证，不能因目录不同就声称“天然不污染”。选取的可迁移经验须有证据与授权；复制、改写或摘要本身均不能证明已复核。

| 阶段 | 输入与输出 | 必需边界 |
|---|---|---|
| 工作记录 | 会话、工具结果、产物、验收和失败事实 | 原始来源可定位；不逐条聊天调用模型提炼 |
| 任务记忆 | 当前约束、进度和待解问题 | 服务当前任务；纠错立即修正当前计划，收尾再筛选长期价值 |
| 长期岗位记忆 | 有价值且有适用条件的事实与经验 | 保存来源、环境/版本、有效性与争议；重复出现不自动提高可信度 |
| 私人职业 Skill | 可重复方法、资源、检查及失败处理 | 保留员工/部门/岗位归属；原稿与可用版本分开，不把一次任务整体固化 |
| 通用候选 | 从新增或修订的纳管 Skills 提炼方法 | 另建候选，保留私人原版；删除私人信息和不可共享内容，但保留方法所需条件 |
| 验证与发布 | 对明确候选的检查、独立批准、不可变版本 | 作者不能自批；验证目标模型及工具环境，未验证范围不宣称通用 |
| 分配与使用 | 管理员选择获准版本，Host 合法加载 | 发布不自动替换已分配版本或扩大权限；分配、加载、效果分别核对 |
| 纠错与撤回 | 失效记录、派生版本及加载者范围 | 停用受影响贡献并处理已加载上下文；只删源文件不等于影响消失 |

**DEP-D07：通用化是保留条件的提炼，不是删细节比赛。** 删除一个要素后已有样例仍通过，只能作为该样例的证据；不能证明跨模型、跨环境有效。选用有代表性的成功/失败场景检查适用范围。研究、创作类使用明确评价标准及独立评审记录；模型评审不称为人工验收。证据不足时保留候选或限制适用范围，不自动发布给所有员工。候选正文或资源变化后，旧批准不直接执行，仅重做受影响验证。

**DEP-D08：整理按增量触发。** 执行中发现错误先修正当前任务；任务收尾筛选经验，空闲周期先检查新增/变更，无新增则不调用模型。业务优先，整理可取消、去重和恢复。矛盾经验按条件与版本分开，不能以更新日期、重复次数或多数模型意见直接覆盖事实。

Skills 系统纳管个人职业 Skill 不等于可以扫描所有私人记忆。员工提交候选及获授权的必要证据；其他模型只得到获准内容。正式通用版本能否作为独立部门资产在个人解雇后保留，仍为 DEP-O04，不能提前复制可还原个人档案的内容来绕过删除要求。

### 10.7 审计、误判与政策变更〔建议〕

**DEP-D09：审计模型提供判断，Host 执行授权与事实检查。** 建议审计独立于被审管理员、技能作者和发布执行者，向操作者或其授权上级报告，不产生第二条业务派工链。初期可使用一个按事件调用的专属会话；组织形式、授权主体和私人调查范围仍为 DEP-O05。模型品牌不同不能单独证明独立性。

| 动作 | 建议处理 |
|---|---|
| 日常记忆维护、使用获准 Skill | Host 校验身份、归属、版本及状态；留痕并按需抽查，不逐次等待审计模型 |
| 疑似污染或不胜任 | 先检查任务、工具环境、指令、记忆及 Skill 版本；必要时可逆暂停受影响动作，有界复核，不先认定员工有错 |
| 发布或迁移知识 | 独立审查者核对准确候选、授权与实际证据，执行前重核当前版本和任职 |
| 私人记忆调查 | 只读获授权案件中的相关片段，记录目的、范围及访问者；常规审计不能默认读取全部私人内容 |
| 审计规则与自身经验修改 | 基于可核验案例独立复核；不由审计模型批准扩大自己的权限 |

**DEP-D10：按问题分类，不给员工贴永久标签。** 分别记录事实错误、环境/版本过期、适用范围不符、权限问题和风格差异，允许多个问题并存；未知保持未知。风格不同本身不构成污染，但违反明确产出要求可作为质量问题，不能混称事实错误。

历史行为依据**当时生效**的规则判断；当前知识是否可继续使用依据**现在生效**的条件检查。标准收紧不追溯地把原先合规行为判错。待执行批准在相关任职、候选或条件变化后须重核；不因此抹掉所有历史审查。误判解除时恢复受影响工作前检查当前授权，不自动恢复已撤销权限。

每次结论分别记录事实、推断、缺失证据和建议动作，绑定对象与版本；执行后读回。审计记录由 Host 追加及授权访问，模型不能修改过去的记录；这不是防御任意宿主文件写权限的保证。审计队列按增量、优先级、去重及可恢复处理。

审计模型不可用时，既有授权和获准版本下的普通工作继续；必须审查的发布、调查或删除等待相应处置，不能静默跳过。明确的上级决定也要留痕，不能把审计变成全部业务的串行瓶颈。

### 10.8 解雇与删除边界〔需求 + 建议分列〕

**DEP-R04 的已确认边界**是删除全部个人档案、保留必要人事办理过程。部门成果、通用 Skill 及历史会话混合内容如何处置仍需 DEP-O04 定案。

**DEP-D11〔建议〕**：先完成必要交接并确认旧执行停止，再按清单处理个人资料、头像、灵魂/操作文档、记忆、私人 Skills、个人会话及可恢复副本。分别列出索引、缓存、备份和派生内容；无受支持的删除方式或无法证明清除时记录未完成，不使用“删除了入口文件”作为全部完成的证据。

人事记录仅保存办理所需的员工编号、任职关系、申请/决定/执行主体、原因及必要证据摘要、时间、交接结果和删除结果，不复制私人正文。保留员工编号意味着仍存在必要历史关联，不能声称完全匿名或不可关联。批准者与提案者、执行者的具体关系见 DEP-O01；审计模型不得自行决定扩大保留范围。

| DEP-A01 / R01、D04 | 无部门、无管理员时创建部门，再任命和招募 | 顺序可读回；首任初始化不依赖其自批或先领取正式业务任务；只有一个当前直接汇报关系 |
| DEP-A02 / R03、D04 | 缺头像、操作文档或记忆初始化时尝试派单、自领、自动调度，再补齐并重启 | 三条正式任务入口均拦截缺项；补齐后可就绪，重启不丢检查状态，合法初始化仍可进行 |
| DEP-A03 / R02、R04、D05 | 管理员替换/员工调岗时存在在途任务和排队消息 | 旧执行被确认处理；员工身份保留，新映射合法，冷恢复可用；任务不悬空、不重复执行 |
| DEP-A04 / R05、D06 | 调岗前存在旧部门私人知识，在新岗位发起检索 | 新工作不自动召回受限旧内容；获准选择的经验可按证据迁移，私人目录与纳管归属可读回 |

| DEP-A06 / R06、D07、D08 | 有/无增量时触发整理；发布前修改候选；错误版本已被他人加载 | 无新增不调用模型；旧批准不用于新候选；受影响派生版本和加载上下文均被处理 |
| DEP-A07 / D09 | 审计模型离线或积压 | 普通获准工作继续，必审动作等待；恢复后可按既有记录继续，不伪造批准 |
| DEP-A08 / R04、D11 | 解雇删除途中失败并重启 | 旧身份不可工作；同一办理流程恢复，完成清单才报告完成；人事记录不夹带私人正文 |
| DEP-A09 / R07、D02、D10 | 同一表达在创作/审查部门评价；随后收紧部门规则 | 按职责与当时规则解释结果；当前使用重新检查，风格差异不自动变成历史污染 |
| DEP-A10 / D03、D05 | 部门任职与 Team 引用不一致，或仅更改队长绑定 | 冲突显式可见，受影响新增动作停下，回到各自权威恢复；不按最后写入覆盖其他域 |
| DEP-A11 / R04、D05 | 冷处理后触发任务/唤醒，再以变化后的岗位或权限恢复 | 冷处理保留档案且不继续工作；恢复重新校验，不复活旧权限 |

## 11. 单人多部门公司的重构合同

### 11.1 对象与模块

**ORG-01：一个本地公司根，多部门、多项目。** UI 首版管理一个公司，数据保留稳定 organizationId，不以全局常量隐含所有权。用户始终有暂停/恢复入口；Main Brain 可获授权协调，不设必须在线的 AI CEO，也不取消授权范围内的自治。

| 对象 | 最小内容 | 职责与边界 |
|---|---|---|
| Organization | ID、操作者/委托引用、控制版本、运行政策 | 长期组织与授权入口，不是正式任务总表 |
| Department | 公司、职责/产出/边界、岗位/能力、行为政策版本、管理员任职、生命周期 | 一名当前管理员，可有多个项目/Team；详细规则沿用 DEPT-01–04 |
| Employee | 稳定 ID、公开资料引用、个人资产索引、生命周期 | 管理员也是员工；不随模型或 Session 更换而换身份 |
| Appointment | 员工、部门/岗位、直接汇报关系、权限引用、起止与代际 | 首版一个当前主属部门；参与多个项目不等于调岗或第二人事汇报线 |
| ExecutionBinding | 真实 Session、员工、任职、授权代际、创建来源、装配版本引用、有效性 | Host 管理的执行连接；初始化即可建立，无须 taskId，不复制 attempt 状态 |
| Project | ID、负责部门/负责人、参与部门、目标/交付契约、Team 引用 | 成果归集与跨部门协作，不另存任务进度 |
| Team / Session | 既有权威 | Team 拥有任务、attempt、审核、邮箱；官方 Session 保存真实输入与执行历史 |
| Artifact / Skill | 稳定 ID、版本、归属、适用范围、访问条件、来源 | 资料室登记和现有 Skills 各司其职，不复制正文到组织档案 |

组织先做插件内一个内聚领域模块，沿官方持久化扩展；准入组合现有 Team mutation，装配属于 Host，UI 只做投影。记忆、Skills、资料室沿用各自权威。不按每个名词拆 Service、包、数据库或调度器，只有实际生命周期/发布边界需要时才拆分。

个人文档集由 Host 的个人资产保存边界持久管理：员工在本人权限内提交内容，保存所有者/任职用途、文档类型、不可变 versionId、内容及摘要、前版引用与保存结果；Employee 只持当前引用，不把私人正文塞进公开 Team profile。正文先耐久保存，随后以预期前版 CAS 提升当前引用，失败保留可恢复候选而不假报生效；必需资格变化遵循 ORG-05。表 schema、验证和迁移同步声明，重载须读回同一版本/摘要；装配证据回指该实际版本。这是现有存储扩展的逻辑边界，不要求另建服务。

### 11.2 权限、个性与入职

**ORG-02：汇报单一，沟通按授权开放。** 用户创建部门并授权首任任命；这一授权可覆盖入职满足后的激活，无须每步重复确认。管理员只在获准本部门范围招募、分配岗位和办理人事，不能自我升权或撤换其他管理员。项目负责人不因此得到人事权。

候选管理员和员工使用受限初始化入口，允许本人保存、读回、修正资料及验证装配，不先领取正式业务任务；不能自批任命。无就绪管理员是合法 awaiting_manager 状态，用户可补任/恢复。创建用稳定操作 ID 幂等重试，不因超时重建员工。

用户建公司/部门及首任任命从公司页的显式操作进入 Host/RPC mutation，由真实 local-operator 权威校验对象、当前权限、预期 revision 和稳定 operationId。Main Brain 获授权时可调用同一能力，但每次从真实执行上下文重验委托范围/有效性，不能把 Main/Captain 文本或常驻布尔标志当操作者。首片只创建新的合法员工和 Session；旧 Session 纳管未交付前不允许通过任命入口偷偷建立其 Appointment。

**ORG-03：完整必要入职，增量复核。** 派单、自领、调度、重派/重试的新 attempt 共用准入判定：有效任职和权限代际；公开资料与非空有效头像；SOUL/性格、OPERATING/操作规范、记忆初始化和岗位必需能力；文件实际保存、所有权/版本读回；Host 对当前版本的实际请求装配；所需工具/能力的最小验证。初始记忆允许空集合，不编造经验。模型自报、文件存在、assigned Skill 标志均不能独自形成 ready。

装配证据关联 Session/request、任职代际、源版本/摘要与装配组件版本，证明系统实际装入内容，不冒充模型理解质量。撤回或新增必需项在后续执行前复核；普通笔记/头像变化只失效相关部分，不一律重跑全套入职。资格缺项显示原因和修复入口，可恢复等待，不误记预算耗尽、终结整个目标或持续忙重试。

**ORG-04：文件指导行为，不授予权限。** 部门按职责分别设置表达、探索、流程等维度，受 Host 授权上限约束。OPERATING 分别引用强制岗位规则与员工个人方法；Markdown 内容不能直接增加工具/资料权限。个人在既定范围内修改 SOUL、笔记或方法无须逐项审批；影响他人职责、共享政策或公共 Skill 发布须经过对应权威。强制重大人格改写及异议的最终业务权利仍为 DEP-O02，候选不默认授权。

### 11.3 执行一致性

**ORG-05：可信身份与共同提交窗口。** 从真实执行上下文取得 Session，查 Host Binding，再核对 Employee、当前 Appointment/代际、Team roster 及操作权限。模型传 employeeId 不是凭据，Session/Employee/Appointment ID 不直接比较相等。

首版每个员工跨 Team 最多一个正式 attempt；等待输入不释放 owner，直到 Team 合同确认提交、取消或移交。被动收信/目录不占新执行；咨询用当前合法会话和有界队列，不另开同时写工作的 Session。初始化/恢复入口也不能与其业务执行构成绕过。

单 Host 先采用一个短时组织协调临界区，覆盖 claim、撤权、调岗、冷处理、控制代际切换及必需资格变更。固定顺序为组织协调入口 → Team 事务；禁止 Team 持锁反向等待组织。优先复用符合合同的已有机制，不额外堆员工锁；临界区不调用模型、不等远程任务或长时间 drain。结束/移交与新占用判断也按一致顺序读取 Team 权威，不由各 Team 分别猜空闲。

所有产生或替换 attempt 的 TeamDomainPort 及 runtime/工具/调度入口必须接入同一前门，首片验收的遗漏清单为空；不能只包装新公司 UI。已绑定员工的其他 Team/Session 也不得绕过，新重构工作缺少绑定时应显示初始化缺项，不得作为旧成员默认放行；旧环境的历史行为仅供参考。组织临界区内按固定顺序读取权威，或使用在门内重建/校验的投影；若用水位，必须在提交前证明覆盖全部相关占用变更。无需强制非事务快照，更不能靠提交后发现冲突来撤销已返回成功的旧事实。

操作流程：可信 Session + 稳定 operationId → 组织协调入口（writer 有效且恢复完成）→ 查同操作已有结果 → 重核当前资格、暂停及跨 Team 占用 → 保存必要恢复意图 → **Team 同次持久提交 attempt 和 operationId 关联** → 更新可重建索引/结果引用 → 提交后发布、放行执行。

Team attempt 提交是 claim 生效点。恢复意图不是第二任务状态机；Binding 在初始化建立，不于 claim 后重造身份。索引失败、回包超时或未知结果先按 operationId 查 Team 事实，查不清就阻塞相关新增动作，不能换 ID 重领。启动重建/核对占用与未决操作后才放行；旧数据双占用要显示冲突，不任意覆盖一条。

恢复操作结果可记录 pending/committed/void。只有完成必要恢复扫描、确认原提交不会迟到且 Team 权威证实未提交，才能在同一前门幂等作废并解除占用阻塞；缓存/索引无记录不是未提交证明。未知仍阻止该员工其他新 operationId 重复占用，不阻断无关员工。按 operationId 查权威及恢复水位是首片依赖；不可判定时提供操作者诊断/修复入口，但不得凭猜测放行。

**ORG-06：实际单 writer。** 公司写入启用前，对规范化存储身份必须存在可验证的真实独占或等价 fencing；第二 Host 被拒绝，失权旧 writer 无法写。公开能力未知必须验证，缺失就不能启用公司写入，不能只写“不支持多 Host”。不为此建设分布式共识系统。

撤权先提交则拒绝后到 claim；claim 先提交则撤权处理其在途事实。新 step/有副作用动作按当前权限代际拦截，已发出的外部副作用不能假装撤回。控制提交、停止请求、实际停止和清理完成分别显示。

### 11.4 替换、调岗与处置

**ORG-07：准备、撤权、接管完成分开。** 正常更换可先准备候选、完成入职并验证合法控制路径，再在短协调窗口提交旧代际失效和切换计划；紧急撤权可先停旧权。旧消息保留来源，消费时拒绝失效管理动作，不自动把旧私密输入交给继任者。

切换用可恢复 operationId 串联各域，不声称共同原子。候选 ready、旧权失效、在途处理、新合法控制路径及冷恢复均可验证后才报告接管完成。父子关系不可迁移时验证公开 Host 桥接或新 Team/Session 的合法延续；旧任务保留/取消/继任关联仍由 Team 记录。不得改历史 parent 或只改 captainSessionId。

失败时用户可查看旧/新任职、已提交步骤、受影响工作和阻塞，继续重试、另选候选或保持无管理员；旧执行停不下则不能重复接管该工作。重新任用旧管理员必须新代际，不复活旧令牌。调岗选择授权资产重装；冷处理在业务执行停止或合法移交后才完成；部门撤销不等于批量解雇。

解雇沿 DEP-D11 清单与必要人事记录。混合历史/通用成果/备份的权利或真实删除能力未定，可完成撤权隔离，但最终删除保持待处置；不假报完整解雇，不复制档案绕过删除要求。

接管验证分两条独立证据链：个人文档版本及装配可在冷恢复后重建；合法父子控制/新执行接线可实际继续工作。前者不能替代后者。任何预期取消、移交或 drain 集合须在执行前由获授权操作记录声明；实际被清退范围不得超出它，并核对无重复工作及续接/移交结果，不能事后把意外全队 drain 改称预期。

### 11.5 记忆、资料室与成长

**ORG-08：分层归属，有条件迁移。** 明确个人、任职/岗位、部门、项目资产及用途；个人目录保留员工资产，资料室/Skills 按授权登记引用。长期经验保留来源、适用任务/环境/版本、有效性、争议和替代关系。任务中及时纠错、收尾筛选，空闲整理只消费增量，有预算/去重/取消/恢复，无新增不唤醒模型。

失效、未验证、越范围或秘密不能直接默认召回；矛盾经验保留条件，不以两次重复、多模型赞同或最近日期判真。调岗默认停用旧岗位受限记忆/Skills，保留获准人格和可迁移经验；新 Session 不直接载入旧工作整段上下文，权限、过滤、装配共同验证。关键词去除或审计模型自报都不是无污染证明。

个人职业 Skill 按员工/部门/岗位纳管；通用化只读本人提交或明确获准来源，不扫描所有私有记忆。保留私人原版，候选携带适用条件、反例及来源；沿现有 Skills 独立验证/批准、不可变版本、显式分配和实际加载归因。公共批准不授予额外工具权、不自动替换在用版本。错误源撤回要定位派生版本和已加载上下文、停用并重装，不只删源文件。

资料室替代共享目录的登记、授权定位、版本/可用性管理职责；目录仍可承载文件。资料室不取代 Team 公共消息/任务、Session 日志或 Git。保存、可见、通过审查、当前可用沿 LIB-01–11 分开。

### 11.6 自治、跨部门与审计

**ORG-09：自主方法，受控交接。** 员工在目标/预算/工具和资料范围内自主工作及选择协作者，正式汇报归本部门经理。目录只提供获准的职责、能力、可用性和来源时间；不透露私有记忆，也不据模型名称猜图像/工具能力，派发时重核。

普通获准咨询无需经理逐条批准，以来源、稳定 requestId、接收对象、资料授权、期限和回复引用记录。需要接收部门正式劳动时，由其管理入口接受/拒绝并关联唯一 Team 任务；其他部门不能直接给其员工派正式任务。交接明确输入、产物、责任、验收者、失败返回和原任务依赖；重复请求不重复建任务，返件不等于通过审核。

复用现有 durable mailbox/outbox、scheduler、目标控制和用量事实。公开发言不等于唤醒/消费；必要请求有界定向投递。按因果请求限制跳数、已访问接收者和期限，默认不全公司广播；重复回复不循环唤醒。整理优先级低于业务。

预算首版采用对 Team 有限预算的显式分配/预留、一致检查及实际费用归属，防跨 Team 双花和重复汇总；没有原子预留能力就不宣称公司硬上限。咨询、整理和模型审查同样计费。未知用量不填零，也不能据此新增预算授权；计量延迟和估算限制明确可见。

用户暂停公司/部门阻止所属新 attempt、自治协作及后台整理；在途收尾、查看、必要控制和审核仍可用。“立即停止执行”另行报告请求/实际停止；恢复重核资格与预算，不恢复失效授权；错过多个整理周期只补一个有界增量批次。

独立审计先用按事件调用的专属模型能力，不强制常驻部门。Host 执行硬权限和持久检查，模型分别陈述事实/推断/缺证/建议；必审发布/重大迁移绑定准确版本及非作者。疑似不胜任先排查任务要求、工具环境、记忆/Skill 版本，不先归咎人格。私人调查须案件授权；审计不能自批升权，离线不阻断普通获准工作。未决人事权仍沿 DEP-O01/02/04/05。

### 11.7 入口、状态与迁移

**ORG-10：公司 → 部门 → 成员/工作/资料室。** 左侧部门可展开成员；部门工作页汇总项目及 Team 真实引用。点成员先资料，再“发送消息”进入当前合法 Chat；多个上下文显示所属工作供选择，旧任职 Chat 明示历史。去掉每人下方重复“资料”按钮，不靠底部普通会话列表切部门。

部门概览不伪装一个混合所有 Team 的群聊；已有 Team 公共消息仍各有唯一来源。无 Team/管理员给出建立或恢复入口。长期部门公告若以后需要，先确定消息权威，不能拼接个人 transcript。普通会话名称/历史不强制改固定格式，显式关联组织后显示对应模式及真实执行入口。

状态按维度分开：部门运行/管理、员工任职、入职缺项、Team 执行/待审/阻塞、Session 在线/未知；带来源时间、原因和恢复动作。空闲不是完成，提交不是验收，未知不是空闲，暂停不是已完成冷处理。元数据订阅、分页和按需读取，不持续扫描目录/全员日志或让模型总结状态。

Markdown/代码、图片、音视频、HTML 预览/打开沿原群聊格式 Issue 独立交付，不因组织重构删掉 UI 修复。HTML 显式选择并隔离执行能力，不作为当前应用脚本执行；媒体失败说明原因，不扩展成媒体编辑器。

**ORG-11：新重构入口与历史参考分离。** 当前范围是新代码、新团队的公司工作闭环；不要求为旧 Team 保留第二套运行模式或准入旁路。未建立合法员工、任职和 Session 绑定的会话，只能进入受限初始化或显示缺项，不能以“未绑定的独立 Team”身份领取正式工作。旧文档中“独立 Team 原样支持”的规则已由用户本次重构方向取代。

历史 Team 数据与会话保留为已有事实，不因整理文档而删除、迁移或改写。后续只有用户明确要求迁移时，才按具体对象制定映射、在途工作收敛及恢复方案；当前新团队验收不以兼容旧执行器为前置条件。

### 11.9 上游错误停止与用户通知

**ORG-13：上游错误立即停线，直接通知用户。** 用户于 2026-09-15 明确要求；本节是已确认需求，写入文档不代表实现或安装完成。API 上游错误包括鉴权失败、额度/账号不可用、限流、服务端错误、连接失败、超时、流中断及无法继续处理的协议响应错误。第一次观察到错误就停止发生错误的执行，暂停依赖该失败请求的后续派工、自动重试和自动续跑，立即通过现有用户界面报告；不等待模型自行总结，不先耗尽重试次数才告知，不自动切换账号池或模型来继续工作。既有“有界重试”建议不适用于本节的上游错误；恢复须有用户明确指令，充值或健康检查恢复本身不等于恢复执行授权。

停止必须保留团队、成员身份、任务、attempt、已提交产物及 Session 历史，并记录实际错误/中断事实；不能把执行停止改写为任务完成、取消、人员移除或团队归档。团队归档、解散、删除及批量取消任务，必须事先取得用户对具体对象和动作的明确授权，错误处理分支不能代替授权。分别报告“已请求停止”和“已确认停止”，停不下的动作明确告知用户，不能伪报已停止。用户授权恢复时从既有事实续接，避免重复执行已提交操作。

通知至少给出发生时间、受影响团队/任务、模型路由、去敏错误码/原因、实际停止状态以及等待用户处理的事项。不得携带密钥、账号凭证、完整提示词、私有记忆或完整日志。首个错误立即可见；同一故障的重复事件合并计数，不反复刷屏。通知通道故障不能触发业务自动恢复，也不能使站内错误提示消失。

**后续通知扩展：本轮仅预留契约和空接口位置，不实现短信或邮箱发送。** 插件的通知方式选择、配置读回与真实发送能力作为同一后续切片交付。以下是接口契约占位，不宣称已有运行接口，不引入新消息服务或供应商 SDK：

| 预留项 | 契约与当前边界 |
|---|---|
| 插件通知设置 | 预留 `notification.channel = in_app / sms / email`；站内错误提示始终保留。短信/邮箱本轮标记“待实现”，不得出现看似可用的发送入口；后续通过插件选择并读回生效方式 |
| 外部接收目标 | 预留 `recipientRef`，由未来受保护的通知配置解析；错误事件只传引用，不在日志、团队消息或请求中携带完整收件地址/手机号及凭证 |
| 错误事件 | `UpstreamFailureNotice` 预留 `eventId`、`occurredAt`、团队/任务/Session/请求引用、provider/model、去敏错误和停止状态；可复用现有事件与持久记录，不建立第二套任务状态机 |
| 通道接口 | `NotificationChannel.send(notice, recipientRef)`；短信/邮箱空实现只能返回 `not_implemented`，未配置返回 `not_configured`，不能返回成功或静默吞错 |
| 发送结果 | 预留 `accepted / delivered / failed / not_implemented / not_configured`，附关联事件和通道结果引用；请求被接受不等于送达，不支持送达回执的通道明确标记未知 |

具体短信/邮箱供应商、收件目标、凭证接入与送达回执能力留待该切片实施时配置；这些待定项不阻塞上游错误立即停止、保留事实和站内通知。验收见 ORG-A09、ORG-A10。
