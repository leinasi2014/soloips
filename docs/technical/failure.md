# 失败与恢复

> 技术架构 §10。装配失败、上游 API 失败、恢复策略。

## 单包失败

**不等于整体失败**。需区分：

| 失败类型 | 说明 |
|---|---|
| bundle 解析失败 | 拒绝本次 profile 加载 |
| Loader 挂载失败 | 单包挂载失败，后续继续 |
| 依赖 pending | 等待依赖就绪 |
| 客户端激活失败 | 客户端层问题 |

**不得从"某包出错"推断整体失败**。

## 上游 API 失败（红线）

| 错误类型 | 处理方式 |
|---|---|
| 鉴权错误 | 首次出现 → 立即停线 → 通知用户 |
| 额度/配额错误 | 首次出现 → 立即停线 → 通知用户 |
| QPS 超限 | 首次出现 → 立即停线 → 通知用户 |
| 连接错误 | 首次出现 → 立即停线 → 通知用户 |
| 流中断 | 首次出现 → 立即停线 → 通知用户 |

**规则**：

1. 首次出现立即停线
2. 通知用户
3. **不自动重试**
4. **不换路由**
5. **不归档**
6. 恢复须用户明确指令

## 装配失败

| 场景 | 处理 |
|---|---|
| bundle 解析失败 | 拒绝 profile 加载 |
| patch 命中缺失行 | warn + 跳过 |
| config 字段缺失 | warn + 跳过 |
| patch 语法错误 | 拒绝加载 |

## 恢复策略

### 状态恢复

1. 确认恢复点（schema、版本、数据）
2. 在隔离环境验证
3. 用户确认后切换
4. 核对修复结果

### 装配恢复

1. 停止写入
2. 确认单 writer 边界
3. 恢复旧装配
4. 读回验证

## 注意事项

- **不承诺撤销已发生的外部副作用**
- **文件存在 ≠ 内容有效**
- **写入成功 ≠ 重启后能读回**
- **patchReload: live ≠ 重启后保持**
