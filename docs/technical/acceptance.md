# 验收场景

> 技术架构 §11。S0/S1 的验收条件与检查点。

## S0 验收目标

**运行接通与恢复**。公司/部门/员工能建立，工具可调用，重启后可继续。

### 验收条件

| # | 条件 | 验证方式 |
|---|---|---|
| 1 | 公司/部门/员工能建立 | 创建请求成功，读回正确 |
| 2 | 真实工具可调用 | 实际调用并观察结果 |
| 3 | 重启后可继续 | 写入 → 停止 → 重启 → 读回 |
| 4 | 写权独占 | 同实例只有一个 writer |

### 验收检查清单

- [ ] 新公司/部门/员工能建立，缺项能修正
- [ ] 真实 PTC 会话完成文件工具调用
- [ ] RLM 在适合的检查中实际可调用
- [ ] 用户从工作入口看到目标、负责人、待回答问题
- [ ] 审查绑定具体作品版本
- [ ] 用户退回后有明确责任人继续修订
- [ ] 上游 API 错误停止受影响链路并直接通知
- [ ] 写入 → 停止 → 重启 → 读回验证

## S1 验收目标

**短剧 IP 与 PV 交付**。任务领取、制作工具 job、镜头/合成、审查、提问与接续。

### 验收条件

| # | 条件 | 验证方式 |
|---|---|---|
| 1 | 任务能领取 | 领取操作成功 |
| 2 | 制作工具 job 能提交 | jobId 返回 |
| 3 | 镜头/合成能保存 | 写入成功 |
| 4 | 审查能绑定版本 | 审查引用准确版本 |
| 5 | 失败保留已成功素材 | 失败后检查已完成镜头 |

## 验收原则

1. **安装 ≠ 调用**：包安装了不等于功能可用
2. **构建 ≠ 验收**：代码构建成功不等于用户成果
3. **源码 ≠ 版本**：源码改了不等于目标安装已更新
4. **验收分层**：安装 → 装配 → 调用 → 验收 层层验证

## 证据要求

每次验收必须提供：

1. **操作**：做了什么
2. **结果**：实际观察到
3. **验证**：如何核对
4. **适用**：适用于什么范围
