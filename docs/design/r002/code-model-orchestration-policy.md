## 0. 规则来源（用户原话）

1. **「从现在开始你定一个规范，代码的开发你都要让队员使用临时工进行开发。调用 qwen 和 glm-5.3，qwen 用多一些。」**
2. **「调用者负责代码的审查和优化。」**

---

## 1. 核心规则

### R1　代码开发一律由临时工执行

**持久队员不直接编写产品代码。** 所有 `packages/**` 与 `profiles/soloips/**` 的代码产出，由**任务负责人通过 `workflow` 派遣一次性子智能体（临时工）**完成。

| 角色 | 做什么 | 不做什么 |
| --- | --- | --- |
| **任务负责人**（持久队员） | 定义任务、拆解、给验收判据、**审查代码**、**优化/修正**、决定是否再派 | **不亲自写产品代码** |
| **临时工**（`workflow` 子智能体） | 按规格写代码、给证据、报告不确定项 | 不承担跨轮记忆、不决定架构、不自行扩大范围 |

**理由**：用户明确要求；且临时工**不占 8 人编制**（Skill §8.6），可并行铺开。

### R2　模型配额：qwen 为主，glm-5.3 为辅

| 模型 | provider / model id | 配额 | 用途 |
| --- | --- | --- | --- |
| **Qwen** | `qwen` / `qwen3.8-flash-next` | **主力（多数任务）** | 常规实现、测量探针、小步改动、批量代码 |
| **GLM-5.3** | `zai-coding-cn` / `glm-5.3` | **辅助（少数任务）** | 疑难实现、交叉复核、需要第二判断的场合 |

**配额判据**（可核对，不靠感觉）：**同一批任务中，qwen 承担的任务数应严格多于 glm-5.3**。建议比例 **2:1 至 3:1**。

**glm-5.3 的推荐用法**——用于**需要独立第二意见**的地方，而非平均分摊：
- 复杂逻辑或多文件改动 → qwen 主写，**glm-5.3 交叉复核**
- 两模型结论冲突 → **不得投票了事**，须回到一手证据（源码/实跑）裁定
- **不让同一临时工既写又审自己**（与 R3 同源）

### R3　调用者负责审查和优化

**派工者（任务负责人）对临时工的产出负最终责任**，包括：

| 必须做 | 说明 |
| --- | --- |
| **审查** | 核对实际改动与规格是否一致；不满意即**打回重做或自行修正**，不因"是临时工写的"而放行 |
| **优化** | 补一致性、补边界、补错误处理、统一风格；**不得把未经审查的产出直接当作交付物** |
| **证据核验** | 临时工给 `file:line`、命令、退出码；**调用者须抽查关键结论**，不采信自报 |
| **署名与责任** | 交付物中如实说明"由临时工执行、由 X 审查优化"，**不隐瞒执行者** |

**明确的责任边界**：临时工**不是责任主体**——它是一次性资源。**产出不合格是调用者的问题。**

### R4　与既有规则的关系（不冲突，是叠加）

| 既有规则 | 本规范的关系 |
| --- | --- |
| **DEV-12 单写者** | 临时工**仍受约束**：同一时间一个文件只有一个写者。并行铺开时按文件/模块切分写面 |
| **Skill §8.6 临时工规则** | 本规范是其**代码开发场景的具体化**；§8.6 的留档、证据标准、边界要求**全部继续适用** |
| **R5 作者不得自审** | 临时工写的代码，**调用者审查不算"独立复核"**——独立复核仍须**另一名非作者成员** |
| **G1–G4 闸门** | **不因使用临时工而减少**。G1 架构评审、G3 提交复核、G4 验收照旧；仅 G2 的代码由临时工产出 |

## 2. 执行方式

### 派工模板（`workflow`）

```js
const r = await agent(PROMPT, {
  label: "impl:<功能>-<切片>",
  phase: "<阶段名>",
  provider: "qwen",              // 主力；疑难用 "zai-coding-cn"
  model: "qwen3.8-flash-next",   // 或 "glm-5.3"
  schema: RESULT_SCHEMA,         // 要求结构化回报，便于机器核对
});
```

### 每个临时工任务的必填内容

1. **目标行为** + 需求/验收 ID
2. **允许写入的确切文件**（写面独占）
3. **接口/契约**（已冻结的签名与 schema）
4. **验收判据**（什么算完成、什么不算）
5. **证据要求**：`file:line`、实际命令与退出码、已验证/未验证/未执行分开
6. **停止条件**：遇到什么停下来问，而不是自己猜

### 留档（强制）

临时工产出**必须落到任务交付目录**，不得只留在临时工会话里。
- 代码本体：进正常代码落点（经调用者审查后）
- 过程证据（探针、试错、放弃的方案）：`.artifacts/operations/<任务>/workers/`
- **明确标注哪个临时工（模型 + 标签）产出了哪一部分**

## 3. 不得使用临时工的情形

| 情形 | 原因 |
| --- | --- |
| 需要**跨轮记忆**的连续重构 | 临时工每次是新实例，会丢失上下文导致不一致 |
| **架构决策**（接口设计、边界划分） | 属持久队员职责；临时工只执行已定规格 |
| **同一可写面的连续修改** | DEV-12 单写者；应由同一执行者完成 |
| **独立复核** | R5：不得由产出者自审——临时工不能复核自己写的代码 |
| **需要真实凭据或生产数据** | 项目红线；临时工不接触凭据 |

## 5. 反面声明

- 本规范是**执行方式约束**，**不构成任何实现授权**。产品实现仍需用户授权（基线 §6 A3）。
- 使用临时工**不放宽任何验收要求**：SOLO-ACC 场景、G1–G4 闸门、DEV-13 证据标准均不变。
- **不因临时工产出而降低复核强度**；恰恰相反，因执行者无持久上下文，**调用者的审查责任更重**。
