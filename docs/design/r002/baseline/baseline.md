### 出口的判定纪律（反面声明）

- 「bundles 数组含包名」**不是**装配证据；必须给 L2 生效树中的对应行 + 一次功能探针（SOLO-REG-04）。
- 「进程退出码 0」**不是**组合正确证据；未命中 patch 可 warn/skip（SOLO-F06）。
- 「清空数据后能启动」**不算**恢复通过（SOLO-ACC-05）。
- 「同实例 already-open」**不能**替代跨 Host 独占证据（MECH-05、SOLO-ACC-09）。
- 「构建成功」**不是**产品验收（项目红线）。
- 通知的 `accepted` **不等于** `delivered`（SOLO-ACC-08）。

## 4. 证据格式（DEV-13 / ENV-04）

每个出口交付时给出：

1. **实际输入与哈希**：涉及的工件、锁、配置文件及其 SHA-256。
2. **基线**：宿主/插件版本组合、profile、解析后 home、有效存储根、`patchReload` 实际取值。
3. **命令与退出码**：工作目录、去敏后的命令、退出状态、相关 stdout/stderr。
4. **通过边界**：本条证明什么、**不证明**什么。
5. **证据分层**：**已验证 / 未验证 / 未执行分开写**，不得用无范围汇总数替代回执。

装配、安装、实际调用、冷启动恢复、目标集成、用户最终验收**分别记录**，一层证据不得替代另一层。
