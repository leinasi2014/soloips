## 0. 为什么需要本文（缺口陈述）

| 角色 | 现状 | 缺口 |
| --- | --- | --- |
| `doc-reviewer` | 只审质量（格式、标注、ID、链接、登记一致性），**只读** | 审出问题但**不负责落点与生命周期** |
| `integrator` | 管 `docs/**` 写入，**同时是 Git 集成者** | 写入权与归档判定是两件事；它无归档判据可依 |

**结果**：`docs/design/r002/` 现为 36 个子目录、135 个文件，混合了**设计正文、探针输出、替身包 fixture、复核脚本**四类内容，其中**仅 12 份 Markdown 登记**，非 Markdown 残留**全部未登记**。没有规则能回答「这个文件该不该在 `docs/` 里」。

本文给出规则。

## 1. 三类文档的边界与判据

### 1.1 分类判据（按顺序判定，首个命中即定类）

```text
产物是「结论」还是「得出该结论的过程」？
├─ 结论（可被下游直接消费：设计、契约、架构、决策）→ 【交付物】
└─ 过程
   ├─ 是否可重放？能否据它复现结论？
   │  ├─ 能，且是结论的证据 → 【证据回执】
   │  └─ 不能独立成立（只是运行的副产物）→ 【实验残留】
   └─ 是否含机器路径/瞬时状态/凭据？→ 是则**只能**落本机记录（§4）
```

### 1.2 三类定义

| 类别 | 定义 | 判据（须全部满足） | 落点 | 是否入库 |
| --- | --- | --- | --- | --- |
| **交付物** | 承载结论、供下游消费的正文 | ① 有独立结论或契约；② 被其他产物引用；③ 脱敏后语义不变 | `docs/design/<版本>/`（或既有 `docs/<类别>/`） | **必须入库** |
| **证据回执** | 证明结论成立的过程记录 | ① 绑定输入与命令；② 可据它复核结论；③ 有明确消费者 | `docs/design/<版本>/<册>/evidence/`（随所属交付物） | **入库**（小体积、可读） |
| **实验残留** | 运行副产物，不承载结论 | ① 可由脚本重建；② 或仅为中间态；③ 无独立读者 | `.artifacts/operations/<任务>/`（本机，被忽略） | **不入库**；确需随交付物同行时按 §3.3 |

### 1.3 判定示例（用现有产物校准，避免抽象）

| 产物 | 类 | 理由 |
| --- | --- | --- |
| `mechanism-audit/audit.md` | 交付物 | 承载 MECH-01–10 三态裁决，被 assembly/qa 引用 |
| `adapter/contracts-design.md` | 交付物 | 冻结契约，批 2 的依赖面 |
| `adapter/probe/*.ts`（9 探针 + tsconfig） | 证据回执 | 编译回执的输入，可重放 |
| `assembly/probe/*.txt`（34 文件） | 证据回执 | 探针原始输出，被 `probe-log.md` 引用 |
| `assembly/evidence/baselines/L{1,2}.golden.txt` | 证据回执 | 门禁基线，必须与正文同行 |
| `assembly/evidence/fixture/home/**`（36 文件 + 11 profile） | **实验残留（特殊）** | 可由 `rebuild-stubs.mjs` + `stubs.manifest.json` 重建；见 §3.3 |
| `assembly/tools/*.mjs`、`doc-review/*.py` | 证据回执 | 生成上述证据的工具，可重放 |
| `doc-review/*.json`（scan.json 等） | 实验残留 | 中间扫描数据，结论已进 `review.md` |

## 2. 登记要求

### 2.1 哪些**必须**进 `document-registry.yaml`

| 类别 | 是否登记 | 理由 |
| --- | --- | --- |
| 交付物 | **必须** | 需要变更权归属与 `updateTriggers`（registry 第 5 行是归属唯一权威） |
| 证据回执 | **仅当**它被正文以「结论依据」身份引用 | 登记成本 vs 收益；未被引用的回执无独立变更权需求 |
| 实验残留 | **不登记** | 无独立读者，登记会膨胀注册表 |

### 2.2 `relatedPaths` 使用规则（承接 registry 第 7 行，不重复其正文）

**规则**：`relatedPaths` 用于**同一 `documentId` 名下、共用角色/负责人/变更权**的正文。**上限建议 15 条**——超过说明该条目已承载多个主题，应拆分或改用一份索引。

**当前实践**（`r002-design-index`，11 条）：一份索引 + `relatedPaths` 承载多份分册，**成立**，因其共用 `role: reference` 与同一负责人。

**判定**：一份文件该进 `relatedPaths` 还是独立 `documentId`？

| 情形 | 处理 |
| --- | --- |
| 与索引同主题、同角色、同负责人 | 进 `relatedPaths` |
| 有独立 `updateTriggers` 或不同负责人 | 独立 `documentId` |
| 是**证据回执**且被正文引用 | 进 `relatedPaths`（如需追溯）或仅在正文中链接 |

### 2.3 非 Markdown 产物**不登记**

`document-registry.yaml` 的字段语义（`path`、`writeMode`、`role`）面向文档。`.mjs`/`.py`/`.json`/`.txt` **不单独登记**；其归属通过**所在正文的 `relatedPaths`** 或所在目录的索引体现。

**当前缺口（实测）**：`docs/design/r002/` 下 **123 个非 Markdown 文件**全部未登记。按本节规则，其中 `probe/*.txt`、`tools/*.mjs`、`baselines/*.golden.txt` 属**证据回执**，应由所属正文的 `relatedPaths` 覆盖或明确不覆盖；**fixture 属实验残留，不登记**。详见 `.artifacts/operations/r002-doc-archival/registry-additions.md`。

## 3. 镜像规则（**裁定**）

### 3.1 口径差异（须消除）

| 来源 | 口径 |
| --- | --- |
| task-7 描述 / task-13 任务书（Lead 采纳 coordinator 发现） | 「**单向镜像、`.artifacts` 为源**」 |
| `integrator` 在 PR #5 的表述 | 「分用途双向固定」——「`.artifacts` 仅作本机现场记录」「后续产物**直接写入** `docs/design/r002/`」 |

**差异实质**：若「后续产物直接写入 `docs/`」，则 `.artifacts` **不再是源**，单向镜像不成立。

### 3.2 裁定：**分用途单向，不是全局单向**（推荐结论）

两种口径都**不完整**。实际关系是**按产物类别分向**，这是唯一自洽的规则：

| 产物类别 | 方向 | 源（权威） | 理由 |
| --- | --- | --- | --- |
| **交付物** | **单向：`docs/` 是源** | `docs/design/<版本>/` | 受版本控制、需变更权、读者是仓库接手者。**后续交付物直接写入 `docs/`**，不再先写 `.artifacts` |
| **证据回执** | **单向：随交付物** | 与所属交付物同落点 | 证据必须与结论同行，否则读者要跨忽略边界找依据 |
| **实验残留** | **单向：`.artifacts/` 是源** | `.artifacts/operations/<任务>/` | 含机器路径与瞬时状态（规范 §6）；**不得**入库 |
| **历史存量**（已入库的脱敏副本） | **`docs/` 为交付基准** | `docs/design/r002/` | 已脱敏、已登记；`.artifacts` 侧为未脱敏现场，**仅作追溯** |

**因此，正确表述是**：

> **交付物与证据回执：`docs/` 为源，单向入库（`.artifacts` 不再作为源）。**
> **实验残留：`.artifacts/` 为源，单向留本机（不入库）。**
> **两者不互为镜像**——不存在「双向固定」。

### 3.3 特例：可重建的 fixture

`assembly/evidence/fixture/` 属**实验残留**，但因**门禁可重放性**需要同行入库。处置规则：

**允许入库，但必须同时满足三条**：
1. **可重建**：提供重建脚本（`rebuild-stubs.mjs`）与清单（`stubs.manifest.json`）——**已满足**；
2. **保真度分层声明**：明确「工作树内逐字节相同 / 洁净检出因 `.gitattributes` `eol=lf` 有行尾差异」——**已满足**（`fixture/README.md` §3，经 `8930a4b` 更正）；
3. **命名与位置不得误导**：目录名须含 `fixture`/`stub` 语义，且**路径上位于 `evidence/` 之下**——**已满足**（`evidence/fixture/home/profiles/<名>`）。

**第 3 条是本次实测问题的正解**：task-13 任务书担心「目录名像真包名」。实测确认——11 个 profile 目录名（`soloips-arch`/`soloips-exp`/…）**确实像包名**，但其 `package.json` 的 `name` 是 `dsh-profile-soloips-*`（**带 `dsh-profile-` 前缀**，非包名），且**完整路径含 `evidence/fixture/home/profiles/`**。**结论：无需移动，但须在索引中显式标注**（见 §3.4）。

### 3.4 强制标注要求

任何入库的**实验残留特例**，其**最近的索引正文**必须写明：类别、可重建方式、保真度边界、以及「**不得作为真实包使用**」。当前 `r002-design-index` §2 第 3 册已描述 fixture，但**未显式声明「非真实包」**——**补登需求见 `.artifacts/operations/r002-doc-archival/registry-additions.md`**。

## 4. 落点规则（脱敏与敏感信息）

**硬规则**（承接规范 §6，不重复其正文）：**含机器绝对路径、私有网络地址、凭据、瞬时进程状态的产物，一律落 `.artifacts/operations/`（被忽略），不得入库。**

若某交付物**必须**入库但含上述内容，**必须先脱敏**，且脱敏须满足：

| # | 要求 | 理由 |
| --- | --- | --- |
| D1 | 机器绝对路径 → ENV-02 符号环境名 | 规范 §6 |
| D2 | 私有地址 → 占位符 | 仓库 `visibility: public` |
| D3 | **脱敏后语义必须仍正确** | **本轮两个阻断缺陷的教训**：`$SYMBOL` 在 PowerShell 是空串、在 JS 是字面量 → 见 §4.1 |
| D4 | 脱敏范围与方式须可核对 | 索引登记「第 N 类集成者改动」 |

### 4.1 脱敏语义核查（D3 的执行判据，**必做**）

**「路径已消失」≠「替换后仍正确」。** 判据（可机械执行）：

| # | 判据 | 范围 |
| --- | --- | --- |
| V1 | 机器绝对路径 0 命中 | 全树 |
| V2 | 私有地址 0 命中 | 全树 |
| V3 | 凭据 0 命中 | 全树 |
| V4 | **可执行围栏内裸 `$SYMBOL` = 0** | 仅 `powershell`/`pwsh`/`bash`/`sh`/`console`/`cmd`/`ps1` 围栏 |
| V5 | **原生脚本内 `"$SYMBOL"` 字面量 = 0** | `.mjs`/`.ts`/`.cjs`/`.js`/`.ps1` |
| V6 | 替换所用符号名**在 ENV-02 有登记** | 与 `environment-handoff.md` ENV-02 表比对 |

**上下文边界（避免误报）**：`text` 围栏、行内代码、正文中的 `$SYMBOL` 是**符号名的文档化用法，不是缺陷**。实测：全树 57 处裸 `$SYMBOL`，**仅 1 处是真缺陷**。**判据必须带语言上下文**。

**执行者**：写者执行；**独立复核者验证**（DEV-13，不得作者自审）。

## 5. 清理条件

### 5.1 何时**可以**删除

| 条件（须全部满足） | 说明 |
| --- | --- |
| ① 有明确消费者已消失 | 引用它的正文已归档或已更新 |
| ② 可由脚本重建，或结论已进正文 | 删后不损失信息 |
| ③ **非他人成果** | 删除他人产物命中 `AGENTS.md` §2 #6，须先确认 |
| ④ 在版本控制外，或已按 DEV-12 记录释放 | 入库文件的删除须走 PR |

### 5.2 何时**必须保留**

| 情形 | 保留理由 |
| --- | --- |
| 是某结论的**唯一**证据 | 删除会使结论不可复核 |
| 是**门禁基线**（golden） | 重建不等于原基线 |
| 有未关闭的**未结事项**引用它 | 见 `.artifacts/operations/r002-doc-archival/open-items.md` |
| 属他人成果且未确认 | §2 #6 |

### 5.3 保留时的标注要求

保留的残留必须在其**最近索引**中标明：类别、生成者/任务、可重建方式、**释放条件**（何时可删、由谁决定）。**禁止**仅靠文件名表达状态。

### 5.4 本任务**不删除任何文件**

task-13 明确：**不删他人成果**。清理清单只给建议，实际动作交 `integrator` 或经 Lead 授权。
