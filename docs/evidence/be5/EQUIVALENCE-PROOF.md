# 候选 v2 → v2.1 等价性证明

**缘由**：v2 冻结（`65142ec4…`）后，写手应用户指示补写「判定落点规则」注释，工作区 SHA 变为 `acff46aa…`。
按「验证后又改源码 → 旧结论不得沿用」的纪律，必须判定这次改动是否影响 QA 已验的语义。

## 判据（决定性，非人工阅读）

用 **TypeScript 编译器自身去注释**后逐字比对（`ts.transpileModule` + `removeComments: true` +
空白归一化）。该判据排除了「行尾符差异」（CRLF vs LF）与「注释文本差异」两类噪声，
只保留**可执行代码**。

## 结果

| 文件 | 去注释后比对 |
|---|---|
| `packages/core/src/store.ts` | **相同** |
| `packages/core/src/contracts.ts` | **相同** |
| `packages/core/src/index.ts` | **相同** |

（其余 7 个改动文件在 token 级比对中已全部相同——见下方「比对过程」）

## 结论

**v2 → v2.1 的改动纯属注释**（新增「判定落点规则」小节 + 措辞收紧），**零可执行代码变化**。
故：
- QA 在 v2 上对**代码语义**的验证结论（若通过）**可沿用到 v2.1**；
- 但**候选身份必须更新**——v2.1 的 SHA 与 v2 不同，任何「已验 SHA」的声称都必须指向 v2.1。

## 比对过程（可复现）

1. 以基线 `466df63` 铺底 + 施加 v2 冻结补丁 → 重建 v2 内容于临时目录
2. 与当前 worktree 逐文件比对，用 `ts.createScanner` 收 token（第一轮）、
   随后发现 scanner 把注释当 token，改用编译器 `removeComments` （决定性判据）
3. 首轮出现的 10 个文件「全不同」是**行尾符噪声**（`git show` 落盘为 LF）；归一化后仅剩 3 个文件差异，且全部为注释
