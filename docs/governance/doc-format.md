# SoloIPs 文档格式规范

> 简化版。面向智能体和人类，标注维度最小化。

## 1. 阅读契约

每份实质性文档开头加契约表：

```markdown
| 阅读契约 | 内容 |
|---|---|
| 身份 | 文档唯一标识 |
| 目的 | 一句话说明本文做什么 |
| 范围 | 本文覆盖什么 |
| 依据 | 权威来源 |
| 变更权 | 谁可以改、怎么改 |
```

短文档一句话契约即可：

```markdown
> 本文档记录 X。负责人：xxx。依据：xxx。
```

## 2. 标注系统（简化版）

### 决策维度

| 标签 | 含义 | 规则 |
|---|---|---|
| 〔需求〕 | 用户明确的需求 | 必须有来源（用户消息/Issue ID） |
| 〔约束〕 | 既有工程约束 | 受委托技术决定或既有规则 |
| 〔建议〕 | 设计建议 | 可根据情况取舍 |
| 〔待决〕 | 未决定 | 需要补充信息才能确定 |
| 〔已取代〕 | 被新决定替代 | 引用新决定 |

### 标注规则

1. **复合陈述拆分**：一条陈述只要有一部分是建议，就不能整体标为需求
2. **建议内的"必须"**：只描述该建议成立的条件，不是命令
3. **来源绑定**：需求必须写来源，其他维度默认可推算

### 证据标注（可选）

需要时使用：

| 标签 | 含义 |
|---|---|
| 〔源码事实〕 | 带来源和版本的观察 |
| 〔推断〕 | 含假设的推断 |
| 〔未验证〕 | 未知或证据缺口 |

## 3. 稳定 ID

需要跨引用的需求、决策、场景分配稳定 ID：

- 格式：`SOLO-01`、`ARCH-D01`、`DEV-01`
- 重写保留原 ID
- 含义改变时标出取代关系

引用时写 ID，不写"如前所述"。

## 4. 文档结构

### 推荐顺序

```
1. 阅读契约（契约表或一句话）
2. 目的与范围
3. 核心内容
4. 决策/规则/设计
5. 待决事项
```

### 规则写法

行为规则写清楚：

- **谁**（actor）
- **何时/前提**（trigger/precondition）
- **做什么**（action）
- **结果**（outcome）

### 反面声明

需要时写"这条不蕴含什么"：

- 持有 ≠ 可访问
- 安装 ≠ 被调用
- 构建 ≠ 验收

## 5. 引用规范

- 仓库内文件：用相对路径或稳定 ID
- 外部来源：用直链
- 源码事实：`来源 + 版本/日期 + 边界`

## 6. 维护原则

1. **单一权威**：更新最小既有正文，不新建同题副本
2. **投影不复制**：投影只引用权威，不重复内容
3. **待决显式**：保留未决项并标注
4. **更新同步**：改权威时更新相关引用

## 7. 简化说明

相比原 `agent-readable-documentation.md`：

- 去掉"交付维度"标注（提案/已实现/已验证/已集成）
- 去掉复杂的 front-matter 格式要求
- 证据标注改为可选
- 强调实用性而非完整性

**理由**：标注维度越多，维护成本越高。对中小型项目，决策维度足够；交付状态在 Git 历史和 Issue 里追踪更直接。
