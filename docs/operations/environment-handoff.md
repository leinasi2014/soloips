# SoloIPs 环境定位与运维交接

| 阅读契约 | 内容 |
| --- | --- |
| 身份 | `SOLO-ENV-HANDOFF`；本项目环境定位与本机交接的查阅规程 |
| 目的 | 将技术架构中的符号环境名解析为有证据的本机位置，避免把源码、磁盘配置与运行服务混为一体 |
| 范围 | 源码/需求来源定位、目标安装与数据根确认；具体部署或恢复动作按任务授权执行 |
| 决策状态 | 〔约束〕承接用户补齐开发前资料的要求、ARCH-D03/04/07 与文档规范 §6 |
| 证据范围 | 本文规定如何取得与刷新环境证据；机器路径和当次观察存放于本机记录，不构成持续运行保证 |
| 依据 | [技术架构附录 B](../technical-architecture.md)、[项目绑定](../governance/project-binding.yaml)、[代码规范](../governance/code-development-standard.md) |
| 变更权 | 规程按[注册表](../governance/document-registry.yaml)维护；执行者只在当前授权范围内更新本机观察 |

## ENV-01：先读本机记录

本机记录固定放在仓库根 `.artifacts/operations/environment.local.md`，由 `.gitignore` 排除；接手者先检查该文件，再核对本次动作涉及的字段。该文件是带时间的观察记录，既不替代原生任务系统，也不新增运行状态权威。

新 checkout 没有本机记录是正常情况。接手者按下节重新定位或从当前运维负责人取得记录，不能把另一台机器的路径填作已验证值。记录缺失仅阻止依赖这些证据的动作；已授权且与真实环境无关的离线工作可以继续。

记录至少包括：观察时间与主机、符号名、绝对路径/定位值、只读证据、已证边界、尚缺证据，以及刷新触发。命令取证必须记录工作目录、去敏后的命令/参数、退出码与相关 stdout/stderr；非命令工具记录成功/失败状态，未提供退出码时标为不适用，不补造 0。空输出只有结合成功状态才能解释。禁止写入密钥、鉴权头、完整环境变量、用户会话内容或未经筛选的进程命令行。

## ENV-02：符号如何核实

| 符号或对象 | 必须取得的证据 | 不能据此推断 |
| --- | --- | --- |
| `AGILE_SKILL_ROOT` | 按绑定 `method.name` 在当前会话技能目录中定位 SKILL.md，核对 frontmatter 的 name，再解析真实目录；无目录入口时使用本机交接记录并复核文件。多处候选不一致时核清所加载版本 | 这是执行者的查阅步骤，不是仓库已经实现的自动 resolver；找到目录不证明技能执行效果 |
| `SOLOIPS_ROOT` / `LAUNCH_ROOT` | 前者由当前 checkout 与 Git 顶层核实；后者由相关进程的启动记录与启动器位置关联，历史文件按记录日期使用 | 当前工作目录不自动等于运行器目录；历史交接不证明当前服务状态 |
| `DSH_CHECKOUT` | 实际目录、Git HEAD/脏状态、相关包 manifest；与目标官方 tag/commit 对照 | checkout 版本不等于已安装或正在运行的版本 |
| `REFACTORING_DOCS_ROOT` | 实际目录及 README、01–04 文档存在；核对本次引用的 ORG/验收 ID | 找到目录不等于所有旧需求已适配新工程 |
| `COMPANY_CORE_CHECKOUT` 等复用候选 | worktree 实际位置、HEAD、相关文件与改动边界 | 候选提交不等于 55120 已采用 |
| `DSH_HOME_LIVE55120` / `PROFILE-55120` | 55120 listener → owning process → 启动器/获准读取的 home 与 profile 参数；再核对对应 manifest、lock、安装包与 overlay | 端口存在或某 home 的文件存在都不能单独证明归属；磁盘配置也不证明进程已应用 |
| `DSH_HOME_OTHER` | 能明确定位的历史观察来源与本次用途；不需要时保留未知 | 不能借它替代 55120 的安装或状态证据 |
| 新 SoloIPs 的生产/验证/恢复根 | 按 SOLO-DATA-01–04 分别记录 home、profile、backend、业务/Session/资产根、规范化身份及 overlay 来源 | home 名不同不证明实际数据或锁域隔离；计划路径不代表已经创建 |

## ENV-03：按动作补齐证据

| 即将执行的动作 | 动作前需要的交接 | 完成边界 |
| --- | --- | --- |
| 文档、离线设计与获授权的工程骨架 | 相关源码/需求位置、候选兼容目标与写范围 | 不依赖生产数据与服务状态；工程配置按 DEV-14 在切片内交付 |
| 隔离安装或 Host 验证 | 精确宿主/插件工件与校验值、依赖锁、完整 profile/overlay、测试专属根、进程与端口归属、资源释放办法 | 配置、安装、实际行为分别取证；禁止使用生产 Session 和真实业务数据作为临时样本 |
| 操作 55120 或切换正式入口 | 当前进程/安装/根的归属证据、受影响范围、在途任务与停写/排空方式、恢复负责人及覆盖具体动作的授权 | 未核实的字段先补齐；观察到端口或读到 manifest 不授权重启、改配置或启用写入 |
| 真实状态恢复 | 上一行条件，以及一致检查点、schema/工件兼容、媒体与外部 job 对账、有效新数据的处置方案 | 按 SOLO-ACC-06 的相应分支验证；回退装配与回退状态分别证明 |

用户会话和生产目录的深入检查仍遵守当前授权；为了填交接表，不运行故障注入、`dump-config`、模型请求或会改写配置的启动命令。查询失败时明确缺失证据，按项目停线边界处理受影响动作。

## ENV-04：刷新与交付

- 文档或源码核验的回执必须绑定实际输入范围：文件列表及内容哈希、相关提交与脏状态、检查时间、检查器/命令身份、退出状态和结果。链接数注明扫描文件、排除项及按出现次数还是唯一目标计数；候选或范围变化后另存新回执，保留旧回执的原范围，不以扩大扫描后的数字覆盖历史。
- 进程重启、启动参数/profile/overlay/依赖/数据根变化、换主机或开始相关部署动作前，重新核实相应字段；旧观察保留为来源，不能继续标成当前事实。
- 只提交本规程与规则变更。本机记录和脱敏核验输出留在忽略目录；向其他执行者交接时明确位置、时间与未证边界，不把它们混入源码提交。
- 维护者保留当前有效本机记录用于接手；被新观察取代的本任务临时输出在没有剩余消费者后清理。具体任务状态、成员进度与运行验收结果仍进入既有任务/交付系统。
